# رحلة المستخدم وتجربة الخدمات التشاركية — InWork

## المبدأ الحاكم

InWork منصة خدمات تشاركية ذكية متعددة المجالات. ليست منصة نقل، ولا تُحصر في الحرف أو مدينة واحدة. تُضبط فئات الخدمات ونطاقات التغطية بحسب استراتيجية التشغيل، مع قابلية إضافة مجالات جديدة دون تغيير جوهر المنتج.

نستفيد من أنماط UX العامة التي تجعل رحلة الطلب والعروض والاختيار واضحة وسريعة: إنشاء طلب، استقبال عروض، مقارنة البدائل، ثم اختيار مقدم الخدمة. هذا استلهام وظيفي للتجربة وليس نسخًا لهوية أو أصول أو واجهات أي منتج آخر.

## مسار طالب الخدمة

1. **الدخول والاكتشاف:** يختار المستخدم مجال الخدمة أو يبحث مباشرة بالكلمات المفتاحية.
2. **تحديد الاحتياج:** يكتب عنوانًا ووصفًا واضحًا، ويحدد النطاق الجغرافي أو يختار خدمة عن بُعد عند ملاءمتها.
3. **تحديد التوقعات:** يضيف ميزانية استرشادية أو موعدًا أو متطلبات خاصة، وكلها اختيارية بحسب نوع الخدمة.
4. **استقبال العروض:** تظهر عروض مقدمي الخدمة المؤهلين مع نطاق العمل والسعر والمدة ووقت الاستجابة.
5. **المقارنة والاختيار:** يقارن المستخدم الخبرة والتقييمات والتفاصيل، ويختار العرض الأنسب. التفاوض متاح فقط عندما تسمح طبيعة الخدمة وسياسة المجال بذلك.
6. **التواصل والاتفاق:** تُوثق تفاصيل النطاق والسعر والموعد قبل تأكيد الطلب.
7. **متابعة التنفيذ:** حالات واضحة للطلب من الإرسال إلى القبول والتنفيذ والإكمال أو الإلغاء.
8. **التقييم:** بعد الإكمال، يمكن للطرفين تقديم تقييم وفق سياسة المنصة.

## مسار مقدم الخدمة

1. إنشاء ملف مهني يتضمن التخصص والمهارات والوصف ونطاق التغطية.
2. إضافة الخدمات التي يقدمها وأسعارًا استرشادية أو طريقة تسعير مناسبة.
3. ضبط التوفر واستقبال الطلبات المطابقة.
4. إرسال عرض يوضح السعر والنطاق والمدة وأي شروط لازمة.
5. التواصل مع طالب الخدمة وتحديث حالة الطلب.
6. إكمال الخدمة وتلقي التقييم.

## مبادئ UX المشتركة

- Mobile-first مع دعم كامل للعربية RTL والإنجليزية LTR.
- تقليل الخطوات والحقول إلى الحد اللازم لطبيعة الخدمة.
- عرض الأسعار والنطاق والمدة بوضوح، وعدم إظهار تقديرات على أنها أسعار نهائية.
- إبقاء القرار النهائي لطالب الخدمة، دون اختيار آلي غير معلن.
- إبراز التوثيق والتقييمات ومؤشرات الإنجاز مع بيان معناها وحدودها.
- إظهار حالات التحميل والفراغ والخطأ والنجاح بوضوح.
- توفير بديل يدوي عند تعذر الموقع الجغرافي أو أي تكامل خارجي.
- عدم افتراض أن كل الخدمات محلية؛ دعم الخدمات عن بُعد والخدمات ذات النطاق المحدد.

## حدود النسخة الحالية

الواجهة الحالية نموذج تفاعلي لاستكشاف تجربة الاستخدام. حفظ الطلبات فعليًا، الحسابات، التحقق من مقدمي الخدمة، الرسائل، العروض، الدفع والإشعارات تحتاج إلى استكمال وربط طبقة الخادم وقاعدة البيانات وسياسات الوصول قبل اعتبارها وظائف إنتاجية.
